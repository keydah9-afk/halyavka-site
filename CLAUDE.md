# halyavka.net — ГДЗ-сайт (Astro, статика)

- Запуск: `pnpm dev --port 4399` (см. `.claude/launch.json`). Билд: `pnpm build`.
- Стек: Astro + Tailwind (`darkMode: 'class'`), View Transitions (`astro:page-load` в скриптах компонентов).
- Бренд: червоний `#C1121F`, темно-синій `#003049`, кремовий `#FDF0D5`; тёмная тема через `:global(.dark)`.
- Классическое ГДЗ: ответы = webp-картинки в `public/images/<klas>/<book>/`, данные книги в `src/data/<author>-<subject>-<klas>.ts`, страница в `src/pages/<klas>-klas/gdz-.../index.astro`, просмотрщик — `ExerciseGallery.astro`.
  Структуру (§, розділи, состав вправ) для новых книг брать из HTML-файла `зміст`, который
  пользователь кладёт в папку книги, — это точные данные, навигатор от NotebookLM для них НЕ нужен.
  Парсеры-генераторы data-файлов: `scripts/gdz/` (там же README и что делать, когда доедут
  недостающие блоки). Обязательная проверка перед сдачей — плоский список кнопок против реальных
  файлов в `public`: 0 missing / 0 extra / 0 dup. Имена файлов приводить к схеме СТАРОЙ страницы,
  иначе ломаются внешние deep-link-и `/…/#123`. Трекер всей пакетной работы — `PERENOS-STATUS.md`.

### Мостик между площадками

У `ExerciseGallery` появился опциональный проп **`deepLinkBase`**: если он задан, под
просмотрщиком появляется ссылка «🧠 Покроковий розбір цього завдання», и её href
пересобирается при каждом переключении номера. Для остальных книг проп не задан —
ничего не меняется. Обратный мостик (с поддомена сюда) — в `BookHero` поддомена, поле
`mirror` в его `src/data/books.ts`.

### Рендерер картинок из текста

Живёт только на поддомене — `himiya.halyavka.net/scripts/`, рядом с исходными текстами
(держать копию здесь смысла нет: без данных она всё равно не запустится). Приём общий
и переиспользуемый: **если у книги есть текстовые ответы, картинки к ней можно нарисовать,
а не сканировать.** SVG → sharp, без браузера. Строки в `answer` уже разбиты по 72 символа,
поэтому перенос слов не нужен; пустая строка массива = половинный отступ на картинке.

## Деплой: смоук-тест и Cloudflare

Последний шаг `.github/workflows/deploy.yml` («Проверить живой сайт») ходит на
`https://halyavka.net/` с раннера GitHub. С 02–03.09.2026 в ответ приходит **403**:
пользователь включил в Cloudflare **Bot Fight Mode**, а тот режет запросы с IP
дата-центров. Сайт при этом жив — с обычного IP отвечает 200.

Поэтому шаг устроен так: 5 попыток с паузой, 200 → успех, **403 → предупреждение
и успех** (это состояние защиты Cloudflare, а не сайта), остальные коды → падение.

**Обойти это правилом WAF Skip на текущем тарифе нельзя:** Bot Fight Mode (в отличие
от Super Bot Fight Mode на Pro+) срабатывает раньше custom rules и не принимает
исключений. Тариф домена — free. Так что варианты ровно три:
выключить BFM, поднять тариф ради Super BFM, либо оставить как сейчас — деплой
зелёный, а живость сайта смотреть глазами. Выбрано третье.

Заголовок `X-Deploy-Check: halyavka-actions` запрос всё равно шлёт — он пригодится,
если тариф когда-нибудь сменится.

**Побочный эффект BFM, который стоит проверить:** он бьёт по автоматическим запросам
без JS, а на сайте живут виджет комментариев Telegram и кнопки шеринга. Верифицированные
поисковые боты (Googlebot) под BFM не попадают, а вот превью-боты соцсетей — могут.
Стоит кинуть ссылку на страницу в Telegram и посмотреть, рисуется ли карточка.
